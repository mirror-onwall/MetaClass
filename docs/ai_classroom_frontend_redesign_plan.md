# MetaClass AI 教室前端改版方案

## 1. 背景

MetaClass 当前已经具备材料解析、Learning Content 生成、Presentation Plan 生成、PPT 生成、课堂计划和多学生智能体互动等完整业务链路，但前端主要采用控制台式三栏布局。随着功能不断增加，页面中的按钮、状态和信息面板越来越密集，课堂空间本身不够突出。

本次改版希望参考 [my_ai_town](https://github.com/mewamew/my_ai_town) 的像素场景表达方式，将课堂首页设计成一间可以观察和操作的 AI 教室。参考重点是“场景、人物和状态反馈”，不引入完整游戏所需的自由移动、碰撞、地图、时间或存档系统。

> 注意：参考项目目前没有统一的根许可证，不能直接复制其代码或美术素材。本项目只参考视觉和交互思路，教室背景、学生角色和界面素材需要重新设计或使用许可明确的素材。

## 2. 改版目标

改版后的课堂主页面需要让教师快速理解以下信息：

1. 当前课程讲到哪个页面和知识点。
2. 当前由教师还是学生智能体发言。
3. 哪些学生正在思考、提问、记录或产生困惑。
4. 当前课堂是否正在播放、等待回答、生成内容或发生异常。
5. 教师下一步可以执行什么操作。

核心体验可以概括为：

> 让教师像观察真实课堂一样观察多智能体课堂，并能直接操作黑板、学生和课堂进度。

## 3. 设计原则

### 3.1 场景优先

教室场景是页面最重要的视觉主体。用户进入首页后首先看到黑板、教师、课桌和学生，而不是大量表单与按钮。

### 3.2 功能保持完整

改版只调整前端信息架构和视觉呈现，不改变现有后端接口及以下业务链路：

- 上传和解析 PDF/PPTX。
- 生成 Learning Content。
- 查看课程大纲和知识树。
- 生成 Presentation Plan。
- 选择 PPT 主题并生成 PPT。
- 创建连续讲解或互动课堂。
- 进行测验、问答、翻页、语音和视频生成。

### 3.3 轻场景而非重游戏

第一版不实现：

- WASD 或鼠标控制角色移动。
- 角色寻路和碰撞。
- 可探索地图。
- 昼夜、天气和复杂物品系统。
- 游戏循环或独立存档系统。

### 3.4 角色必须独立

学生、教师、气泡、桌椅前景和状态图标不能合并成一张不可编辑的大图。每个学生都应是独立 React 元素，便于调整位置、切换状态和响应点击。

### 3.5 视觉特色集中

改版的主要记忆点是“AI 教室场景”。周围的抽屉、按钮和信息卡片保持克制，避免同时叠加大量游戏化装饰。

## 4. 整体信息架构

### 4.1 主页面布局

```text
┌──────────────────────────────────────────────────────────┐
│ MetaClass   课程名称   当前环节 03/08       资料库   设置 │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  ┌──────────────── AI 教室场景 ───────────────────────┐  │
│  │                                                    │  │
│  │       黑板：PPT / 测验 / 当前知识点                │  │
│  │                     教师                           │  │
│  │                                                    │  │
│  │       学生 A       学生 B       学生 C             │  │
│  │       记录中        举手中        思考中            │  │
│  │                                                    │  │
│  │       学生 D       学生 E       学生 F             │  │
│  │       有疑问        听讲中        准备总结           │  │
│  └────────────────────────────────────────────────────┘  │
│                                                          │
│   上一页      自动讲课/暂停      下一页      向老师提问   │
└──────────────────────────────────────────────────────────┘
```

### 4.2 页面区域

#### 顶部状态栏

只保留：

- MetaClass 品牌标识。
- 当前课程名称。
- 当前教学环节和进度。
- 历史资料库入口。
- 主题和设置入口。

#### 中央教室场景

包含：

- 黑板或投影区域。
- 教师角色。
- 6 至 8 个学生座位。
- 学生状态、发言气泡和课堂提示。
- 必要的环境装饰与灯光效果。

#### 左侧备课抽屉

用于承载：

- 材料上传和解析。
- 课件使用路线选择。
- Learning Content 生成。
- Presentation Plan 生成。
- PPT 主题选择和 PPT 生成。
- 创建课堂和生成视频。

抽屉默认收起，仅在备课或生成阶段展开。

#### 右侧课堂抽屉

根据用户当前选择显示：

- 课程大纲。
- 知识树。
- 当前学生详情。
- 最近课堂事件。
- 当前 PPT 页面和讲稿。

#### 底部控制台

集中放置课堂高频操作：

- 上一页。
- 自动讲课/暂停。
- 下一页。
- 用户提问。
- 当前语音播放状态。

## 5. 教室场景结构

建议采用普通 React DOM 叠层实现，不在第一版引入 Canvas 或游戏引擎。

```text
ClassroomScene
├── ClassroomBackground
├── BlackboardSlot
│   └── ActionView
├── TeacherCharacter
├── StudentSeat × 8
├── SpeechBubbleLayer
├── ClassroomEffects
└── ClassroomControlDock
```

### 5.1 背景分层

建议准备以下原创视觉资源：

1. 教室后景：墙面、窗户、书架和黑板边框。
2. 桌椅后层：不会遮挡人物的固定桌椅部分。
3. 学生和教师角色：透明背景的独立图片。
4. 桌椅前景：用于压住角色下半身，形成空间层次。
5. 状态素材：灯泡、问号、笔记本、举手、发言框等。
6. 环境效果：光束、粉笔灰、黑板高光等。

### 5.2 学生座位

每个学生使用独立组件，并通过百分比定位：

```tsx
<StudentSeat
  student={student}
  x={32}
  y={68}
  scale={0.92}
  state="thinking"
  selected={selectedStudentId === student.id}
/>
```

位置和缩放写入统一座位配置，不散落在 JSX 中：

```ts
const classroomSeats = [
  { id: "seat-01", x: 25, y: 58, scale: 0.88 },
  { id: "seat-02", x: 43, y: 58, scale: 0.88 },
  { id: "seat-03", x: 61, y: 58, scale: 0.88 },
  { id: "seat-04", x: 19, y: 76, scale: 1 },
  { id: "seat-05", x: 41, y: 76, scale: 1 },
  { id: "seat-06", x: 63, y: 76, scale: 1 },
];
```

## 6. 学生智能体的状态映射

现有 `session.student_states` 和学生智能体配置可以直接驱动场景，不需要重新设计后端数据。

| 课堂状态 | 场景表现 | 动画建议 |
| --- | --- | --- |
| 正在听讲 | 正常坐姿 | 轻微眨眼和呼吸 |
| 深度思考 | 灯泡或省略号 | 图标缓慢浮动 |
| 举手提问 | 举手状态、座位高亮 | 手臂抬起或整体轻微弹动 |
| 正在回答 | 姓名标签和发言气泡 | 聚光和边缘描边 |
| 记录笔记 | 桌面出现笔记本 | 铅笔轻微移动 |
| 概念困惑 | 问号和橙色提示 | 问号淡入淡出 |
| 总结内容 | 便签或知识卡 | 卡片展开 |
| 等待互动 | 安静状态 | 降低动画频率 |

第一版不需要为每个状态绘制完整人物动画。可以使用一张基础坐姿角色图片，再叠加手臂、道具、图标和 CSS 动画，以降低美术和开发成本。

## 7. 主要交互

### 7.1 点击学生

点击学生后打开右侧详情抽屉，显示：

- 学生姓名和智能体类型。
- 学习特征和角色设定。
- 当前状态。
- 最近一次发言或意图。
- 对当前知识点的理解情况。

### 7.2 学生发言

学生发言时：

1. 对应座位自动高亮。
2. 场景中显示简短发言气泡。
3. 完整内容仍显示在右侧或字幕区。
4. 其他学生降低视觉强调。

### 7.3 用户提问

用户提问入口保留在底部控制台。输入问题后：

- 教师角色进入回答状态。
- 教师气泡显示当前回答。
- 课堂流程暂停时明确提示暂停原因。
- 回答结束后恢复自动课堂。

### 7.4 选择学生智能体

互动课堂创建前，教室内显示空座位：

- 点击空座位打开学生选择抽屉。
- 选中的学生直接出现在座位上。
- 点击已安排学生可以替换或移除。
- 同时保留列表选择模式，兼顾键盘和无障碍操作。

## 8. 不同业务阶段的场景表现

### 8.1 未上传材料

- 教室灯光偏暗。
- 座位为空。
- 黑板显示“把课件带进教室”。
- 点击讲台或材料箱打开上传抽屉。

### 8.2 材料解析和内容生成中

- 教师角色显示备课状态。
- 黑板显示当前生成步骤和进度。
- 桌面出现文件、电脑或便签。
- 用户可以查看详细任务状态，但不能重复创建相同任务。

### 8.3 Presentation Plan 和 PPT 生成中

- 黑板展示页面生成进度。
- 已完成页面可以显示缩略图。
- 主题选择位于备课抽屉中。
- 失败时直接说明失败原因和可执行操作。

### 8.4 课堂进行中

- 黑板显示 PPT、题目或当前知识点。
- 教师和学生状态随课堂动作变化。
- 当前发言者高亮。
- 底部控制台负责翻页、播放和提问。

### 8.5 课堂结束

- 黑板展示课堂完成状态。
- 提供重新播放、生成视频和返回资料库的入口。
- 右侧抽屉可展示课堂事件摘要。

## 9. 视觉系统

### 9.1 颜色

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 黑板绿 | `#294A40` | 黑板和主要教学区域 |
| 教室墙面 | `#E8D8B8` | 场景基础色 |
| 木质棕 | `#916342` | 课桌、讲台和边框 |
| 状态蓝 | `#557EA5` | 选中、正常状态和信息提示 |
| 互动橙 | `#DEA044` | 举手、等待回答和重点操作 |
| 深墨色 | `#26332E` | 正文和高对比文字 |

### 9.2 字体

- 黑板标题：霞鹜文楷、楷体或类似手写字体。
- 界面正文：思源黑体、Noto Sans SC 或系统无衬线字体。
- 页码和状态：DM Mono。
- 像素字体只用于少量英文状态和装饰，不用于长篇中文。

### 9.3 动效

只保留服务于课堂状态的动效：

- 当前发言者的聚光。
- 学生举手、思考和记录。
- 黑板内容切换。
- 左右抽屉进入和退出。
- 教室灯光随业务阶段变化。

避免加入无意义的持续漂浮、粒子和大范围弹跳。

同时支持 `prefers-reduced-motion`，在用户关闭动画时提供静态状态反馈。

## 10. 现有代码改造方案

当前前端的主要复杂度来自：

- `apps/web/src/App.tsx` 约 2600 行。
- `apps/web/src/styles.css` 约 2200 行。
- 课堂、备课、资料、PPT 和任务状态集中在同一个组件中。

建议先拆分展示组件，但暂时将状态和接口调用保留在 `App.tsx`，通过 props 传递，避免一次性重构业务状态。

建议新增：

```text
apps/web/src/features/classroom/
├── ClassroomWorkspace.tsx
├── ClassroomScene.tsx
├── ClassroomBlackboard.tsx
├── TeacherCharacter.tsx
├── StudentSeat.tsx
├── StudentInspector.tsx
├── StudentSelectorDrawer.tsx
├── PreparationDrawer.tsx
├── LessonOutlineDrawer.tsx
├── ClassroomControlDock.tsx
├── classroomSeats.ts
└── classroom-scene.css
```

### 10.1 可以直接复用的部分

- `ActionView.tsx`：继续负责黑板中的 PPT 和测验展示。
- `SlideNarrationPlayer.tsx`：继续负责原始页面和讲解播放。
- `studentAgentChoices`：继续提供学生智能体名称、头像和描述。
- `session.student_states`：继续提供本堂课学生状态。
- 现有课堂翻页、播放、提问和答题方法：只调整按钮所在位置。

### 10.2 暂时不修改的部分

- 后端课堂 API。
- ClassroomSession 数据结构。
- PPT 生成链路。
- Learning Content 和 Presentation Plan 数据结构。
- 历史资料库页面。

## 11. 响应式设计

### 桌面端

- 教室保持 16:9 或接近 16:9 的主要画面。
- 左右抽屉覆盖在场景上方，不挤压教室比例。
- 学生保持固定相对座位。

### 平板端

- 教室占据页面上部。
- 底部控制台换行。
- 左右抽屉改为底部面板。

### 手机端

- 优先显示黑板和当前发言者。
- 学生场景允许横向浏览或缩放。
- 提供学生列表作为场景操作的替代入口。
- 所有场景角色都可以通过键盘焦点或列表访问。

## 12. 实施阶段

### 第一阶段：组件拆分

目标：降低修改风险，不改变现有视觉和功能。

- 提取课堂展示区域。
- 提取黑板和底部控制台。
- 提取学生选择和学生列表。
- 为新教室场景准备独立 CSS 文件。
- 确保前端构建和现有课堂流程正常。

### 第二阶段：静态教室场景

目标：完成新的主视觉。

- 添加原创教室背景。
- 将现有 `ActionView` 放入黑板。
- 添加教师和 6 至 8 个学生座位。
- 支持点击学生查看详情。
- 将备课和课程大纲改为抽屉。

### 第三阶段：绑定课堂状态

目标：让场景真实反映多智能体课堂。

- 使用 `session.student_states` 驱动学生状态。
- 当前发言者自动高亮。
- 映射举手、思考、记录、困惑和总结状态。
- 将语音字幕与对应角色关联。

### 第四阶段：交互和动画

目标：增强沉浸感，但控制复杂度。

- 添加轻量角色状态动画。
- 添加场景阶段切换。
- 优化抽屉、提示和错误反馈。
- 完成平板、手机和低动画模式适配。

### 第五阶段：统一其他页面

目标：形成完整视觉系统。

- 统一资料库、知识树和 PPT 生成页面。
- 整理重复和冲突 CSS。
- 统一字体、按钮、状态色和空状态。

## 13. 验收标准

### 功能

- 原有上传、生成、课堂、问答、测验、语音和视频链路均可使用。
- 教室中可以同时显示 6 至 8 个独立学生。
- 点击学生可以查看详情。
- 当前发言者和课堂状态能够实时更新。
- PPT 和测验可以正常显示在黑板中。

### 视觉

- 首屏视觉中心明确为教室场景。
- 场景、学生和界面控件风格统一。
- 不出现大量长期展开的信息卡片。
- 重要文字在不同背景下具备足够对比度。

### 工程

- 不引入 Godot 或额外游戏引擎。
- 不直接复制参考项目素材和代码。
- `App.tsx` 的课堂 JSX 明显减少。
- 新组件职责清晰，场景样式不污染其他页面。
- `npm run build` 通过。

### 可用性

- 学生角色支持鼠标、键盘和触摸操作。
- 动画不会阻碍阅读和操作。
- 移动端有列表式替代操作入口。
- 错误状态明确说明原因和下一步操作。

## 14. 推荐的第一轮改造范围

第一轮只完成以下内容：

1. 拆分课堂展示组件。
2. 制作静态教室背景。
3. 将 PPT/测验嵌入黑板。
4. 将现有学生智能体放入独立座位。
5. 点击学生打开详情抽屉。
6. 将课堂控制集中到底部。

暂不实现复杂移动和大规模动画。完成第一轮并通过现有课堂流程测试后，再决定是否增加更多场景细节。
